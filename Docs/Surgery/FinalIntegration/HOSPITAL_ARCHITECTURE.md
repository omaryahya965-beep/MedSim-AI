# Hospital architecture

## Scene
`Assets/MedSimAI/Hospital/Scenes/MedSim_Hospital.unity` is the first scene in the build. It is generated by the editor menu **MedSim AI → Hospital → Build Hospital Scene** (`HospitalBuilder.cs`):
1. Copies `MedSim_ER.unity` (the v0.6 clinical scene: corridor, Exam Room 3, Dr. Hassan, Mr. Reyes). The hospital scene keeps its own GUID when it is rebuilt. **The original ER scene is not modified** and is still in the build. Run it on its own with `MedSimAI.exe -clinical-only`.
2. Extends the corridor through the old fire doors to x = 13.8 m: walls, window, lights, wall protection and a teleport area.
3. Adds a **reception lobby** (entrance, desk, seating, bilingual directory). The student starts here.
4. Docks Person 1's `OperatingRoom.prefab` on the corridor at (7.25, 0, 2.92):
   - the vestibule's end wall is opened;
   - automatic sliding doors (`AutoSlidingDoor`) are added;
   - a teleport floor is added.
5. Places Person 2's surgical patient at `ANCHOR_PatientRoot`, the populated tray on the Mayo stand next to the student, and the implants on the back table. It adds contact triggers on 8 targets (used only in VR).
6. Adds Person 3's `SurgeryMechanics.prefab` (real mechanics) and binds the robot to Person 1's arm (6 of 6 joints found by name).
7. Gives the ER's instructor (Dr. Sara Hassan) a `HospitalGuide` and a `SurgicalCharacter` (surgeon role), so **there is one doctor in the whole hospital**. Adds the scrub assistant Sami (Rocketbox `Medical_Male_04`) in Room 02.
8. Adds Person 4's surgical session layer with `hostManaged = true` and `allowMockMechanics = false`.
9. Adds the room signs ("Room 01 · Clinical Examination" / "Room 02 · Surgical Training", bilingual) and the lobby sign.
10. Bakes **one hospital NavMesh** (`Physics.SyncTransforms` first). The exam-room door leaf and the OR door leaves are carving `NavMeshObstacle`s, so a closed door really blocks the path.

## Runtime assembly: `MedSimAI.Hospital`
References the clinical scripts (`MedSimAI`), the surgery assemblies and XRI. Nothing references it, so the clinical and surgical layers still build and test on their own.

| Component | Responsibility |
|---|---|
| `HospitalCoordinator` | The single owner of hospital state:<br>• zones (lobby/corridor, Room 01, Room 02) from the player position;<br>• room requests (voice, directory, keys 1/2/3, walking in);<br>• starts and ends each room's session;<br>• session records and the event log;<br>• guided vs. assessment mode (F2);<br>• routes utterances (`VoiceInteractionManager.UtteranceInterceptor`, `SurgerySessionController.UtteranceInterceptor`);<br>• handles `guide_to_room`, `wait_for_student` and `walk_with_student` actions (`DoctorActionController.ExtensionHandler`). |
| `HospitalIntentParser` | Deterministic bilingual parsing of navigation requests: Room 01/02, corridor, wait, walk with me, restart, where should I go, explain the rooms, skip, clarify when both rooms are mentioned. Palestinian Arabic, MSA and English, with normalisation (ه/ة, ي/ى, alef forms, Arabic digits). Inside a room, only explicit room names count, so «ارفع إيدك» is never misread. |
| `HospitalLines` | Authored bilingual **text** for the guide (welcome, follow me, arrived, wait, door closed, where next…). It is spoken at runtime through the existing speech system. It contains no clinical facts. |
| `HospitalGuide` | Walks the doctor on the NavMesh (`DoctorMovement.GoToPoint`):<br>• `CanReach` checks for a complete path first;<br>• waits when the student falls behind (4.2 m) and resumes at 2.6 m;<br>• `WalkWith` and `Hold` modes;<br>• 150 s timeout. |
| `AutoSlidingDoor` | OR doors open by proximity sensor. While open, their carving obstacles move with the leaves. `IsOpen`/`IsClosed` are read by the guide. |
| `SurgicalRoomBridge` | Starts and ends Person 4's `SurgerySessionController` when the student enters or leaves Room 02:<br>• makes voice and desktop keys exclusive (the clinical voice manager is suspended while the surgical one listens);<br>• filters the scenario's hint rules by mode;<br>• binds `RoomEntryPublisher` and the `R` reset hook;<br>• contact triggers in VR only. |
| `RobotGuidanceAdapter` | Moves Person 1's 6-joint arm with CCD IK to hover over the current resection target during resection objectives. It is a visual guide only: no cutting, no haptics. |
| `ObjectiveHighlighter` | Outlines the current objective's target in guided mode only. |
| `HospitalDirectory` | World-space directory in the lobby. Lists the rooms, mode, language, today's sessions and the DRAFT notice. |
| `InstrumentRespawn`, `FaceCamera` | Small helpers: a dropped instrument returns to its tray slot; signs face the viewer. |
| `HospitalSelfTest` | `-hospitalSelfTest <dir>`: the scripted journey in the built exe, with screenshots, GIF frames and timings. |

## Session isolation
| Room | Scenario | Session object | Event stream |
|---|---|---|---|
| Room 01 | `ER_CHEST_PAIN_001` | v0.6 `SessionManager` (`hostManaged`) | Clinical tracker |
| Room 02 | `OR_TKA_TRAINING_001` | `SurgerySessionController` → `SurgerySessionCore` | `SurgeryEventBus` |

- A session starts when the student reaches the door (guided) or enters the room. It ends when the student leaves (`completed` or `left unfinished`) and is then recorded.
- Only one room session is active at a time.
- Tests and the exe self-test assert:
  - the clinical tracker contains no surgical ids;
  - Room 01 after the operating room starts clean;
  - the surgical bus has exactly one `session.started` per entry.

## Desktop vs. VR
- One scene for both. The XR origin and the desktop player controller come from v0.6.
- The Desktop build has the OpenXR loader removed, for that build only.
- The PCVR build keeps it and falls back to desktop control when no runtime is present (or with `-desktop`).

## Not built
- Multiplayer.
- Additional rooms.
- A persistent save of session records (records live for the app session only).
