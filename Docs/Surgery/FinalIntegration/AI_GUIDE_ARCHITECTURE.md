# AI doctor and guide architecture

## One persistent doctor
**Dr. Sara Hassan** is the same GameObject, voice, name and conversation memory in the lobby, the corridor, Room 01 and Room 02.
- PR #2 had introduced a second surgeon persona ("Dr. Lina Haddad"). It was removed: the surgical scenario's surgeon persona is now Dr. Sara Hassan / «د. سارة حسن».
- In Room 02 the surgical layer drives her through `SurgicalCharacter` (surgeon role), which delegates walking to the same `DoctorMovement`.
- Sami (surgical assistant) is a separate character with his own name in the conversation panel.

## Who answers what
```
student speech / text
        │
        ▼
HospitalCoordinator.HandleUtterance ──(navigation intent?)──► deterministic action:
        │ no                                                 guide_to_room / wait / walk_with / clarify / where-next
        ▼                                                    + an authored HospitalLines text, spoken live
in Room 02? ── yes ──► SurgerySessionController ──► surgical supervisor (proxy /v1/surgery/*, grounded in
        │                                          OR_TKA_TRAINING_001 and the live mechanics state)
        no
        ▼
v0.6 clinical conversation (proxy /v1/…, Instructor or Patient persona, grounded in ER_CHEST_PAIN_001)
```
- **Navigation is deterministic on purpose.** Moving the student is a physical action, so the doctor must never claim a walk or a door she cannot do.
  - `HospitalIntentParser` decides the intent.
  - `CharacterActionRouter.Execute(Instructor, guide_to_room)` runs the action through the existing v0.6 action pipeline (Requested → InProgress → Completed / Rejected).
  - Only the real result is spoken.
  - With no complete NavMesh path (for example a closed exam door) she says so, and the action is reported **Rejected**, not Completed. Covered by the `Navigation_ThroughAClosedDoor_IsReportedAsUnavailable_NotFaked` test.
- **Words are not pre-recorded.**
  - `HospitalLines` are authored text spoken through `SayLive` (live TTS when the proxy is available; otherwise clearly labelled subtitles).
  - Clinical and surgical dialogue is generated by the existing grounded AI routes.
  - No audio recordings of characters exist.
- Inside a room, only an **explicit** room name triggers navigation (`Room02Strong`, `Room01Strong`). Exam instructions («ارفع إيدك», "breathe in") go to the room's AI.

## Language
- The conversation language is held by `AIProviderManager` (v0.4) and is the same for every room. Tested by `Language_PersistsAcrossRooms`.
- All guide lines exist in English and Palestinian Arabic. Arabic UI text is shaped right-to-left (`ArabicShaper`).
- Glyphs the fonts lack (⚠ ✓ ✗ 🎤) are mapped before display.

## Surgical AI (Person 4, unchanged in design)
- **Supervisor:** objective explanations, hints, safety interventions, debrief. It is grounded in the scenario JSON and the live bus state. Offline it uses approved fallback text.
- **Action registry:**
  - the doctor and the assistant can only perform registered actions (for example hand an instrument, locate it, step back, stand beside the student, look at the site);
  - every request is validated against the current objective;
  - the result is published on the bus.
- **Hand-over:**
  1. `assistant.action_requested`
  2. Sami fetches the instrument and holds it out
  3. `assistant.handoff_offered`
  4. the student grabs it (`tool.grabbed` from Person 3's instrument controller)
  5. `assistant.handoff_completed`

  No grab means no completion (`Handoff_CompletesOnlyAfterTheStudentReallyTakesTheInstrument`). The instrument is not re-parented to Sami's hand, so it never fights the XR grab.
- **Assessment** (`SurgicalAssessment`):
  - weighted criteria from the scenario JSON (24 points in the run), scored from bus events only;
  - Arabic criterion notes;
  - hints and invalid attempts are counted;
  - the result is labelled formative, not a certification.

## Modes
`guidedMode` (F2, directory, or voice) is passed to `SurgicalRoomBridge`, which filters the scenario's hint rules:
- **assessment mode** removes proactive hints and the highlighter;
- it **keeps safety interventions**.
